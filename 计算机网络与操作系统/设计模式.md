

设计模式是解决软件设计中常见问题的可复用方案，分为三大类：**创建型**、**结构型**和**行为型**。以下是23种经典设计模式的分类、核心思想及典型应用场景：

---

### 0.1.1 **一、创建型模式（5种）**
处理对象创建机制，提升灵活性和复用性。

| **模式**          | **核心思想**                                                                 | **典型场景**                          |
|--------------------|-----------------------------------------------------------------------------|---------------------------------------|
| **单例（Singleton）** | 确保一个类仅有一个实例，并提供全局访问点。                                      | 数据库连接池、日志管理器。             |
| **工厂方法（Factory Method）** | 定义创建对象的接口，由子类决定实例化哪个类。                                   | 跨平台UI组件创建（如按钮、对话框）。    |
| **抽象工厂（Abstract Factory）** | 提供一个接口，创建相关或依赖对象的家族，而无需指定具体类。                     | 跨主题UI套件（如深色/浅色模式）。       |
| **建造者（Builder）** | 分步构建复杂对象，分离构造过程与表示。                                         | 构造复杂对象（如SQL查询生成器）。       |
| **原型（Prototype）** | 通过复制现有对象来创建新对象，避免重复初始化。                                  | 游戏中的敌人克隆、配置模板复制。        |

---

### 0.1.2 **二、结构型模式（7种）**
处理类或对象的组合，形成更大结构。

| **模式**          | **核心思想**                                                                 | **典型场景**                          |
|--------------------|-----------------------------------------------------------------------------|---------------------------------------|
| **适配器（Adapter）** | 转换接口使得不兼容的类可以协同工作。                                           | 旧系统接口适配新API。                  |
| **桥接（Bridge）**  | 分离抽象与实现，使两者可独立变化。                                             | 跨平台图形渲染（如OpenGL/Vulkan）。    |
| **组合（Composite）** | 将对象组合成树形结构以表示“部分-整体”层次，统一对待单个对象和组合。             | 文件系统目录结构、UI组件嵌套。          |
| **装饰器（Decorator）** | 动态地为对象添加职责，避免子类膨胀。                                           | Java I/O流（如BufferedInputStream）。  |
| **外观（Facade）**  | 提供统一接口简化子系统复杂调用。                                               | 数据库ORM框架封装底层SQL操作。          |
| **享元（Flyweight）** | 共享细粒度对象以减少内存占用（如缓存）。                                        | 文本编辑器中的字符对象池。              |
| **代理（Proxy）**    | 为其他对象提供代理以控制访问（如延迟加载、权限控制）。                           | Spring AOP、远程服务调用（RPC）。       |

---

### 0.1.3 **三、行为型模式（11种）**
处理对象间的职责分配与通信。

| **模式**          | **核心思想**                                                                 | **典型场景**                          |
|--------------------|-----------------------------------------------------------------------------|---------------------------------------|
| **责任链（Chain of Responsibility）** | 将请求沿处理链传递，直到有对象处理它。                                         | HTTP请求过滤器链、审批流程。           |
| **命令（Command）** | 将请求封装为对象，支持参数化、队列化及撤销操作。                               | 事务回滚、GUI操作历史记录。             |
| **解释器（Interpreter）** | 定义语法规则，解释特定语言中的句子。                                           | SQL解析、正则表达式引擎。               |
| **迭代器（Iterator）** | 提供统一接口遍历集合元素，隐藏底层实现。                                       | Java的`Iterator`接口、集合遍历。        |
| **中介者（Mediator）** | 通过中介对象封装对象间交互，降低耦合度。                                       | 聊天室中的消息中转、GUI组件协调。        |
| **备忘录（Memento）** | 捕获对象内部状态并在需要时恢复，支持撤销操作。                                 | 文本编辑器的撤销/重做功能。              |
| **观察者（Observer）** | 定义对象间的一对多依赖，状态变化时自动通知观察者。                             | 事件驱动系统（如消息队列）。             |
| **状态（State）**    | 允许对象在其内部状态改变时改变行为。                                           | 订单状态流转（待支付、已发货等）。       |
| **策略（Strategy）** | 定义算法族并封装，使它们可相互替换。                                           | 支付方式选择（支付宝、微信支付）。       |
| **模板方法（Template Method）** | 定义算法骨架，将某些步骤延迟到子类实现。                                       | JUnit测试框架的`setUp()`和`tearDown()`。|
| **访问者（Visitor）** | 将算法与对象结构分离，便于新增操作而不修改结构。                                | 编译器语法树分析、报表生成。             |

### 0.1.4 **四、设计原则（SOLID）**
| **原则**          | **核心思想**                                                                 |
|--------------------|-----------------------------------------------------------------------------|
| **单一职责（SRP）** | 一个类只负责一个功能领域。                                                   |
| **开闭（OCP）**    | 对扩展开放，对修改关闭。                                                     |
| **里氏替换（LSP）** | 子类必须能替换父类且不影响程序正确性。                                         |
| **接口隔离（ISP）** | 客户端不应依赖它不需要的接口。                                               |
| **依赖倒置（DIP）** | 高层模块不依赖低层模块，二者都依赖抽象。                                       |

---

### 0.1.5 **五、模式选择指南**
1. **创建型模式**：  
   - 需要灵活创建对象时选工厂或建造者。  
   - 全局唯一资源用单例。  
2. **结构型模式**：  
   - 接口不兼容用适配器，动态扩展功能用装饰器。  
   - 简化复杂子系统用外观。  
3. **行为型模式**：  
   - 解耦观察者与被观察者用观察者模式。  
   - 算法可切换用策略，状态驱动行为变化用状态模式。

### 0.1.6 **六、示例：观察者模式代码（Java）**
```java
// 主题接口
interface Subject {
    void registerObserver(Observer o);
    void notifyObservers(String message);
}

// 具体主题（被观察者）
class NewsAgency implements Subject {
    private List<Observer> observers = new ArrayList<>();

    public void registerObserver(Observer o) {
        observers.add(o);
    }

    public void notifyObservers(String message) {
        for (Observer o : observers) {
            o.update(message);
        }
    }

    public void publishNews(String news) {
        notifyObservers(news);
    }
}

// 观察者接口
interface Observer {
    void update(String message);
}

// 具体观察者
class NewsChannel implements Observer {
    public void update(String message) {
        System.out.println("Breaking News: " + message);
    }
}

// 使用
public class Demo {
    public static void main(String[] args) {
        NewsAgency agency = new NewsAgency();
        agency.registerObserver(new NewsChannel());
        agency.publishNews("Design Patterns Released!");
    }
}
```

**总结**：设计模式是解决特定问题的工具箱，理解其意图和适用场景是关键。避免过度设计，结合SOLID原则灵活运用，可显著提升代码的可维护性和扩展性。
