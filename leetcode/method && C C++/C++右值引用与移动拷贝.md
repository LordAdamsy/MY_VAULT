C++11引入右值引用可以减少拷贝构造的次数，多用移动构造。
由于拷贝构造在堆中先分配新的空间，再把原空间释放掉，会导致效率较低
而移动拷贝前后指向同一个堆空间，效率较高
在调用函数赋值时，如：
```cpp
bit::string ret = bit::to_string(1234);
```
若为拷贝构造与拷贝赋值，则效率较低
可使用移动构造与移动赋值：
```cpp
string(string&& s)
:_str(nullptr)
,_size(0)
,_capacity(0)
{
	cout << "string(string&& s) -- 移动构造" << endl;
	this->swap(s);
}

string& operator=(string&& s)
{
	cout << string"string& operator=(string&& s) -- 移动赋值" << endl;
	this->swap(s);
}
```
不需要额外分配空间，直接指向原数据的堆空间。
___
**`支持深拷贝的类，提供移动构造和移动赋值，这时这些类的对象进行传值返回或者是参数为右值时，则可以用移动构造和移动赋值，转移资源，避免深拷贝，提高效率。`**
___
**`右值引用的对象，再作为实参传递时，属性会退化为左值，只能匹配左值引用。使用完美转发，可以保持他的右值属性`**

## 0.1 C++中遇到的问题

```C++
TreeNode* buildTree(vector<int>& preorder, vector<int>& inorder)；

TreeNode *right = buildTree(vector<int> arr1(preorder.begin()+1, preorder.end()), vector<int> arr2(inorder.begin()+1, inorder.end()));
```
编译会报错，分析原因可能是：函数定义为左值引用，而调用时传递的参数为右值，因此报错

解决方法：函数定义部分的左值引用调整为const/函数定义部分采用右值，临时变量通过std::move转换为右值

- **右值引用 (`vector<int>&&`)**：
    
    - 右值引用只能绑定到右值（临时对象）。
    - 在递归调用中，`vector<int>(...)` 是一个临时对象，虽然它可以绑定到右值引用，但每次递归调用都会创建新的临时对象，导致频繁的拷贝和销毁。
    - 如果右值引用参数没有被显式地转移（如 `std::move`），编译器可能会报错或导致未定义行为。
- **左值引用 (`const vector<int>&`)**：
    
    - 左值引用可以绑定到左值，也可以绑定到右值（临时对象），但不会改变右值的生命周期。
    - 当传递一个临时对象（如 `vector<int>(...)`）时，编译器会自动延长临时对象的生命周期，使其在函数调用期间有效。
    - 因此，使用 `const vector<int>&` 可以安全地接收临时对象，而无需担心生命周期问题。
- **`const` 的意义**：
    
    - `const` 表示参数是只读的，函数内部不能修改传入的容器。
    - 这不仅提高了代码的安全性，还允许编译器优化参数的传递。
- **为什么加 `const` 可以解决问题？**
    
    - 如果参数是 `vector<int>&`（非 `const` 左值引用），则只能绑定到左值，无法绑定到右值（临时对象）。
    - 如果参数是 `const vector<int>&`，则可以绑定到左值和右值（包括临时对象）。
    - 因此，加上 `const` 后，函数可以接受临时对象（如 `vector<int>(...)`），并且编译器会自动延长临时对象的生命周期，使其在函数调用期间有效。

右值引用减少拷贝次数的核心在于：

1. **直接绑定到临时对象**，避免创建额外的拷贝。
2. **支持移动语义**，通过转移资源而不是复制数据来优化性能。
3. **减少容器操作中的数据复制**，如移动构造和移动赋值。
